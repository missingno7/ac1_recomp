Input record/replay contracts
============================

Build after tools/build.ps1 has prepared the generated inputs:

    cmake --build build/host-relwithdebinfo --target ac1_input_script_contract ac1_input_window_contract ac1_input_dinput_contract --parallel 16

Run the three executables from the repository root. With the launcher's MinGW
Makefiles fallback, substitute build/host-make-relwithdebinfo. Fixtures write
only to ignored work/. Tests cover parser diagnostics, absolute/relative timing,
extended scans and keypad distinctions, tap releases, modifier snapshots,
record/replay round trips (including multiple samples in one present), physical
DirectInput isolation, physical window-message isolation, Unicode text and
GetCursorPos/ScreenToClient consistency.

Launch:

    powershell -ExecutionPolicy Bypass -File tools/run_gameplay.ps1 -Seconds 300

From PowerShell, extra environment values can be passed as a hashtable:

    ./tools/run_gameplay.ps1 -Seconds 300 -Environment @{ AC1_PROFILE = '1' }

The launcher inherits other environment values, restores its own overrides,
records logs/captures/run.json under work/gameplay/, and kills its own game at
the timeout. It invokes tools/build.ps1 -BuildType RelWithDebInfo -Jobs 16.
If the Ninja compiler ABI probe stalls without output for 30 seconds, it kills
that build process tree and uses the same prepared sources and CMake targets
with MinGW Makefiles. No shared SDK or reference checkout is changed.
The DXVK provider must already be in work/d3d9_dxvk_probe/d3d9.dll.

Format (UTF-8 or ASCII; '#' introduces a comment):

    at 200 tap DIK_RETURN 3
    +100 key LSHIFT down
    +1 tap A 2
    +4 key LSHIFT up
    +10 mouse move 600 300
    +10 mouse left click

'at' is optional before a relative '+frames'. Relative times are measured from
the preceding written command, not from the release generated by a tap. Default
tap/click duration is two presents. Commands must have nondecreasing presents;
generated releases are merged in time order. Coordinates are signed client
pixels. Mouse move controls the virtual cursor; raw 'mouse state' supplies DI
relative axes. Replay uses a fixed US keyboard layout for DIK-to-VK mapping and
text, independent of the desktop's modifiers/toggles. Unknown keys, commands,
invalid buffers/layouts and unreadable scripts give explicit diagnostics.
Replay keeps the guest window active independently of desktop focus. It remains
active after the last command, retaining its last input state.

Set AC1_INPUT_RECORD to an output filename while playing to record guest-visible
changes. Every record has a successful-present index and process elapsed ms.
Raw recorder commands are also accepted by the parser:

    at 200 dik 0x1c 0x80 poll 34 # ms=15260
    at 200 mouse state 1 -2 0 128 0 0 0 0 0 0 0 poll 34 # ms=15260
    at 200 wm 0x100 0xd 0x1c0001 # ms=15261

Raw DI commands do not synthesize WM events: the independently recorded WM
records reproduce those. Optional per-device poll ordinals (reset each present) preserve multiple
state changes within one present; remove 'poll N' when retiming those records
by hand. Recorded milliseconds are evidence, not a second scheduling clock.
The input stream is deterministic; the game's random seed, loading durations
and thread scheduling are not replaced. A script timed for a different menu
layout, save state or resolution may require different actions.
