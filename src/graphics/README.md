# AC1 guest D3D9 bridge bootstrap

This is an independently buildable Windows host bridge for AC1's 32-bit guest D3D9 ABI. Build and run its real native-D3D9 factory / adapter-count smoke test with:

```powershell
cmake -S src/graphics -B work/build/d3d9-bridge -G "MinGW Makefiles"
cmake --build work/build/d3d9-bridge
ctest --test-dir work/build/d3d9-bridge --output-on-failure
```

The bridge exposes a C ABI in `ac1_d3d9_bridge.h`. The runtime supplies checked guest memory resolution, aligned guest allocation/free, and guest-HWND to host-HWND mapping. The COM vtable token family is `0x7e000000` (D3D9 kind 1; device kind 2; surface kind 3; vertex buffer kind 4; index buffer kind 5). `ac1_d3d9_argument_count(token)` returns exact stack-word arity including `this`, 0 for foreign tokens, -1 for malformed owned tokens, and -2 for unsupported methods. Dispatch receives arguments with guest `this` first and explicit COM arguments in source order. Dispatch returns 1 for a real native method call, 0 for a foreign token, -1 for invalid object/ABI state, and -2 for unsupported methods. Only result 1 makes EAX valid; ordinary native HRESULT failures remain normal results. `Direct3DCreate9` loads the absolute system-directory `d3d9.dll` by default. For an explicitly selected native backend, set `AC1_D3D9_LIBRARY` to an absolute Windows DLL path; relative or empty values are rejected, and load/export failures do not fall back to system D3D9. The selected DLL is loaded with safe DLL search flags, including its own directory for private dependencies, and remains loaded until bridge shutdown. The platform factory callback can still replace it for other builds.

The bridge marshals the 32-bit guest `D3DPRESENT_PARAMETERS` and adapter-identifier layouts and returns the native host device as a guest object from `CreateDevice`. It preserves requested presentation values, translating only guest window handles at the host boundary. Observed device methods `CreateVertexBuffer` (slot 26) and `CreateIndexBuffer` (27) return distinct guest COM proxies with native lifetime and `IUnknown` reference handling; non-null shared-resource handles trap as unsupported. Observed device state methods `SetRenderState` (57), `SetTexture` (65, null unbind only), `SetTextureStageState` (67), `SetSamplerState` (69), null `SetVertexShader`/`SetPixelShader` (92/107), and shader constant setters (94/96/98, 109/111/113) are handled. Constant input arrays are guest-range checked and register-count bounded by device caps / D3D9 register limits. Non-null texture/shader guest objects remain explicitly unsupported until proxy kinds exist. Vertex/index buffer methods beyond `IUnknown` remain unsupported and trap; Lock/Unlock staging is not included until an actual guest call proves the path. `GetRenderTarget` (slot 38) and `GetDepthStencilSurface` (slot 40) return guest surface proxies; surfaces support `QueryInterface`, `AddRef`, `Release`, and `GetDesc` (slot 12). Other slots remain unsupported and produce diagnostics. The smoke test checks factory/adapter dispatch, buffer creation/lifetime and tries a hidden-window, windowed native device (no desktop-mode change); the fake-COM checks always exercise the supported ABI forwarding and surface paths, independent of whether native device creation succeeds. It does not render a frame or prove that AC1 reached its D3D9 import.

`GetAdapterMonitor` needs `host_monitor_to_guest` on 64-bit hosts if the guest compares monitor handles. No AC1 HWND exists in this module; the owner of the native window must supply the translation callback. The runtime import/dispatch integration is intentionally not included here.
