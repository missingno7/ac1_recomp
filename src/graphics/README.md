# AC1 guest D3D9 bridge bootstrap

This is an independently buildable Windows host bridge for AC1's 32-bit guest D3D9 ABI. Build and run its real native-D3D9 factory / adapter-count smoke test with:

```powershell
cmake -S src/graphics -B work/build/d3d9-bridge -G "MinGW Makefiles"
cmake --build work/build/d3d9-bridge
ctest --test-dir work/build/d3d9-bridge --output-on-failure
```

The bridge exposes a C ABI in `ac1_d3d9_bridge.h`. The runtime supplies checked guest memory resolution, aligned guest allocation/free, and guest-HWND to host-HWND mapping. The COM vtable token family is `0x7e000000` (D3D9 kind 1; device kind 2; surface kind 3; vertex buffer kind 4; index buffer kind 5; vertex declaration kind 6; texture kind 7). `ac1_d3d9_argument_count(token)` returns exact stack-word arity including `this`, 0 for foreign tokens, -1 for malformed owned tokens, and -2 for unsupported methods. Dispatch receives arguments with guest `this` first and explicit COM arguments in source order. Dispatch returns 1 for a real native method call, 0 for a foreign token, -1 for invalid object/ABI state, and -2 for unsupported methods. Only result 1 makes EAX valid; ordinary native HRESULT failures remain normal results. `Direct3DCreate9` loads the absolute system-directory `d3d9.dll` by default. For an explicitly selected native backend, set `AC1_D3D9_LIBRARY` to an absolute Windows DLL path; relative or empty values are rejected, and load/export failures do not fall back to system D3D9. The selected DLL is loaded with safe DLL search flags, including its own directory for private dependencies, and remains loaded until bridge shutdown. The platform factory callback can still replace it for other builds.

The bridge marshals the 32-bit guest `D3DPRESENT_PARAMETERS` and adapter-identifier layouts and returns the native host device as a guest object from `CreateDevice`. It preserves requested presentation values, translating only guest window handles at the host boundary. The observed Windows `D3DXCheckTextureRequirements` import forwards through absolute System32 `d3dx9_36.dll`; nullable/in-out guest fields are locally staged, checked, alias-preserving, and copied back. This helper is explicitly unsupported on non-Windows builds. Device `CreateTexture` (slot 23) returns a typed texture proxy with COM lifetime; shared handles trap as unsupported. Texture methods beyond `IUnknown` remain unsupported until observed. Device methods `CreateVertexBuffer` (slot 26) and `CreateIndexBuffer` (27) return distinct guest COM proxies; non-null shared-resource handles trap. `CreateVertexDeclaration` (slot 86) scans at most `MAXD3DDECLLENGTH` elements plus the required end marker, copies the bounded guest array, and returns a typed declaration proxy. Declaration `GetDeclaration` (slot 4) queries the native element count, copies through a bounded local array, and writes checked guest outputs; `pNumElements` is output-only and a null element output performs a count query. Device state methods `SetRenderState` (57), `ColorFill` (35; registered surface proxies only, optional checked guest `RECT`), `SetViewport` (47; checked 24-byte guest structure), `SetTexture` (65, null unbind only), `SetTextureStageState` (67), `SetSamplerState` (69), null `SetVertexShader`/`SetPixelShader` (92/107), and shader constant setters (94/96/98, 109/111/113) are handled. Constant arrays are guest-range checked and register-count bounded by device caps / D3D9 register limits. Vertex/index buffer Lock/Unlock staging remains unsupported in the bridge pending integration of the separate bounded staging patch. `GetRenderTarget` (slot 38) and `GetDepthStencilSurface` (slot 40) return guest surface proxies; surfaces support `GetDevice` (slot 3), `QueryInterface`, `AddRef`, `Release`, and `GetDesc` (slot 12). `GetDevice` reuses the existing device proxy when the native COM identity matches and balances the acquired native reference. Other slots remain unsupported and produce diagnostics. The smoke test checks D3DX requirement forwarding, texture/buffer/declaration creation and lifetime, declaration count and round-trip behavior, surface `GetDevice`, `ColorFill`, `SetViewport`, and a hidden-window, windowed native device (no desktop-mode change); the fake-COM checks exercise supported ABI forwarding independently of whether native device creation succeeds. It does not render a frame or prove that AC1 renders or presents a frame.

`GetAdapterMonitor` needs `host_monitor_to_guest` on 64-bit hosts if the guest compares monitor handles. No AC1 HWND exists in this module; the owner of the native window must supply the translation callback. The runtime import/dispatch integration is intentionally not included here.
