# AC1 guest D3D9 bridge bootstrap

This is an independently buildable Windows host bridge for AC1's 32-bit guest D3D9 ABI. Build and run its real native-D3D9 factory / adapter-count smoke test with:

```powershell
cmake -S src/graphics -B work/build/d3d9-bridge -G "MinGW Makefiles"
cmake --build work/build/d3d9-bridge
ctest --test-dir work/build/d3d9-bridge --output-on-failure
```

The bridge exposes a C ABI in `ac1_d3d9_bridge.h`. The runtime supplies checked guest memory resolution, aligned guest allocation/free, and guest-HWND to host-HWND mapping. The COM vtable token family is `0x7e000000` (D3D9 kind 1; device kind 2; surface kind 3; vertex buffer kind 4; index buffer kind 5; vertex declaration kind 6; texture kind 7; pixel shader kind 8; vertex shader kind 9; D3DX constant table kind 10; cube texture kind 11; query kind 12). `ac1_d3d9_argument_count(token)` returns exact stack-word arity including `this`, 0 for foreign tokens, -1 for malformed owned tokens, and -2 for unsupported methods. Dispatch receives arguments with guest `this` first and explicit COM arguments in source order. Dispatch returns 1 for a real native method call, 0 for a foreign token, -1 for invalid object/ABI state, and -2 for unsupported methods. Only result 1 makes EAX valid; ordinary native HRESULT failures remain normal results. `Direct3DCreate9` loads the absolute system-directory `d3d9.dll` by default. For an explicitly selected native backend, set `AC1_D3D9_LIBRARY` to an absolute Windows DLL path; relative or empty values are rejected, and load/export failures do not fall back to system D3D9. The selected DLL is loaded with safe DLL search flags, including its own directory for private dependencies, and remains loaded until bridge shutdown. The platform factory callback can still replace it for other builds.

The bridge marshals the 32-bit guest `D3DPRESENT_PARAMETERS` and adapter-identifier layouts and returns the native host device as a guest object from `CreateDevice`. It preserves requested presentation values, translating only guest window handles at the host boundary. The observed Windows `D3DXCheckTextureRequirements` and `D3DXGetShaderConstantTable` imports forward through absolute System32 `d3dx9_36.dll`; shader bytecode is token-parsed and staged, and the returned constant table is represented by a guest proxy. The observed table methods are `GetDesc` (slot 5), `GetConstantDesc` (6), and `GetConstant` (8); creator/name strings are copied into guest-owned memory and opaque handles remain private to the bridge. D3DX imports are explicitly unsupported on non-Windows builds. Device `CreateTexture` (slot 23) returns a typed texture proxy with COM lifetime; shared handles trap as unsupported. `CreateCubeTexture` (slot 25) forwards the observed creation call into a distinct cube-texture proxy with COM lifetime; shared handles trap as unsupported. Cube `LockRect` (slot 19) and `UnlockRect` (20) stage guest32 `D3DLOCKED_RECT` and lock data by cube face and mip level, preserving native pitch and copying rows for the observed A8R8G8B8 format with null RECT and zero flags; other cube methods remain unsupported. The observed texture `LockRect`/`UnlockRect` path stages `D3DLOCKED_RECT` through guest memory, preserves native pitch, and copies only the 4-byte-per-pixel A8R8G8B8 row data back before native unlock. The implementation currently supports null RECT and flags zero for that observed format; other formats, rectangles, and flags trap explicitly. Device methods `CreateVertexBuffer` (slot 26) and `CreateIndexBuffer` (27) return distinct guest COM proxies; non-null shared-resource handles trap. `CreateVertexDeclaration` (slot 86) scans at most `MAXD3DDECLLENGTH` elements plus the required end marker, copies the bounded guest array, and returns a typed declaration proxy. Declaration `GetDeclaration` (slot 4) queries the native element count, copies through a bounded local array, and writes checked guest outputs; `pNumElements` is output-only and a null element output performs a count query. Device `TestCooperativeLevel` (slot 3) forwards the native HRESULT unchanged. Frame boundaries `Present` (slot 17), `BeginScene` (41), and `EndScene` (42) forward native HRESULTs. `Present` accepts null or checked guest RECTs, a null or guest-HWND-mapped override, and either null dirty data or a bounded guest RGNDATA containing RECTs; non-rectangle region types and data above 16 MiB are explicitly unsupported. Device state methods `SetRenderState` (57), `ColorFill` (35; registered surface proxies only, optional checked guest `RECT`), `SetViewport` (47; checked 24-byte guest structure), `SetTexture` (65, registered 2D/cube texture proxies and null unbind), `SetTextureStageState` (67), `SetSamplerState` (69), `SetVertexShader` (92) / `SetPixelShader` (107), and shader constant setters (94/96/98, 109/111/113) are handled. `CreateVertexShader` (91) and `CreatePixelShader` (106) parse bounded shader-model-3 token streams, skipping length-delimited instruction and comment payloads before staging native bytecode; each returns a typed COM proxy and registered shaders can be bound through the corresponding setter. Other shader profiles stop explicitly. Constant arrays are guest-range checked and register-count bounded by device caps / D3D9 register limits. Vertex/index buffer Lock/Unlock uses bounded guest32 staging with explicit range/flag checks and cleanup on Unlock, final Release, and bridge shutdown. `GetRenderTarget` (slot 38) and `SetRenderTarget` (slot 37) forwards checked registered surface proxies or null and preserves the target index. `GetDepthStencilSurface` (slot 40) returns guest surface proxies; `SetDepthStencilSurface` (slot 39) forwards null or registered surface proxies. surfaces support `GetDevice` (slot 3), `QueryInterface`, `AddRef`, `Release`, and `GetDesc` (slot 12). `GetDevice` reuses the existing device proxy when the native COM identity matches and balances the acquired native reference. Other slots remain unsupported and produce diagnostics. The smoke test checks D3DX requirement/table forwarding and metadata, PS/VS 3.0 creation/binding against native DXVK using dynamically compiled synthetic HLSL, texture lock read/write round-trip, texture/buffer/declaration creation and lifetime, declaration count and round-trip behavior, surface `GetDevice`, `ColorFill`, `SetViewport`, and a synthetic indexed-triangle API sequence on a hidden-window, windowed native device (no desktop-mode change). The triangle test checks native binding/draw/frame-boundary HRESULTs but performs no pixel readback. It does not exercise AC1 draw calls or prove AC1 renders a visible frame; fake-COM checks exercise shader token boundaries and resource-proxy rejection/lifetime.

`GetAdapterMonitor` needs `host_monitor_to_guest` on 64-bit hosts if the guest compares monitor handles. No AC1 HWND exists in this module; the owner of the native window must supply the translation callback. The runtime import/dispatch integration is intentionally not included here.


The device also forwards the observed occlusion query path: `CreateQuery` (118) accepts type 9 and returns a typed query proxy; a null output performs the native capability probe. Query `GetType` (4), `GetDataSize` (5), `Issue` (6; BEGIN/END only), and `GetData` (7; null status polling or a checked DWORD result) preserve native return values, including pending `S_FALSE`. Other query types/methods remain explicitly unsupported. Buffer Lock staging copies writable guest bytes back before cleanup unlock on final Release or bridge shutdown; READONLY staging is not copied back.

The isolated rendering candidate also forwards `SetVertexDeclaration` (87), `SetStreamSource` (100), `SetIndices` (104), `DrawPrimitive` (81), and `DrawIndexedPrimitive` (82), requiring registered typed proxies for non-null resources. `SetTexture` accepts registered 2D and cube proxies plus null unbinds. The native smoke submits a synthetic indexed triangle, checks both draw HRESULTs and presents, with no pixel readback. Set `AC1_D3D9_TRACE_FRAME=1` to log only the first successful draw and first successful Present per bridge lifecycle, with the call counters at those events; it is off by default.
